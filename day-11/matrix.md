# Case 2 — GPTBot with TEST_ALLOW_IPS

## Setup

The Express server was started with the temporary local testing bypass:

```bash
TEST_ALLOW_IPS=127.0.0.1 node server.js
```

This allows the local machine to exercise the verified-bot path while using a crawler User-Agent.

## First Request

```bash
curl -i -A "GPTBot/1.0" http://localhost:3000/
```

## Expected

Because the cache is initially empty, the request should:

1. Be classified as GPTBot.
2. Pass verification through `TEST_ALLOW_IPS`.
3. Normalize the requested URL.
4. Check the cache.
5. Get a cache MISS.
6. Render the React application using Playwright.
7. Store the rendered HTML in the cache.
8. Return the rendered HTML with:

```text
X-Prerender: miss
```

## First Response Evidence

Relevant response headers:

```text
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
X-Prerender: miss
```

The returned HTML contained actual product content generated by React, including product names, prices, and descriptions.

Example:

```html
<div id="root">
  <main>
    ...
    <h2>NovaBook Air</h2>
    <strong>₹74,999</strong>
    ...
    <h2>SonicPods Pro</h2>
    <strong>₹12,999</strong>
    ...
  </main>
</div>
```

This proves that Playwright executed the JavaScript application and captured the resulting DOM.

## Second Request

The exact same request was repeated:

```bash
curl -i -A "GPTBot/1.0" http://localhost:3000/
```

## Expected

The rendered snapshot should already exist in the cache.

The response should therefore contain:

```text
X-Prerender: hit
```

## Second Response Evidence

Relevant response headers:

```text
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
X-Prerender: hit
```

The response again contained the complete rendered product HTML.

This proves the sequence:

```text
First request:

    ↓
verified
    ↓
cache MISS
    ↓
Playwright render
    ↓
cache snapshot
    ↓
X-Prerender: miss


Second request:
GPTBot
    ↓
verified
    ↓
cache HIT
    ↓
return cached snapshot
    ↓
X-Prerender: hit
```

# Case 3 — Spoofed GPTBot Without TEST_ALLOW_IPS

## Setup

The Express server was stopped and restarted **without** the test bypass:

```bash
node server.js
```

`TEST_ALLOW_IPS` was not enabled.

## Request

A request was deliberately made with a fake GPTBot User-Agent:

```bash
curl -i -A "GPTBot/1.0" http://localhost:3000/
```

## Expected

The User-Agent claims to be GPTBot, but the local machine cannot pass the real crawler verification.

Therefore the request must **not** receive prerendered HTML.

It should instead be treated as an unverified request and proxied to the normal Vite origin.

## Response Evidence

The response was:

```text
HTTP/1.1 200 OK
X-Powered-By: Express
vary: Origin
content-type: text/html
cache-control: no-cache
```

Importantly, there was **no**:

```text
X-Prerender: hit
```

and no:

```text
X-Prerender: miss
```

The response contained the raw Vite SPA shell:

```html
<!doctype html>
<html lang="en">
  <head>
    <script type="module" src="/@vite/client"></script>
    <meta charset="UTF-8" />
    <link rel="icon" type="image/svg+xml" href="/favicon.svg" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>demo-store</title>
  </head>

  <body>
    <div id="root"></div>
    <script type="module" src="/src/main.jsx"></script>
  </body>
</html>
```

The important evidence is:

```html
<div id="root"></div>
```

The product catalog is not present in the raw HTML.

The server therefore correctly rejected the spoofed crawler identity and used the proxy path.

## Why Case 3 Is the Most Important Row

Case 3 is the most important security test because a client cannot gain access to the prerendered bot path merely by spoofing a trusted crawler's User-Agent; its network identity must also be verified.

In other words:

```text
User-Agent: GPTBot/1.0

does NOT automatically mean:

verified GPTBot
```

Anyone can change their User-Agent, so User-Agent classification alone cannot establish crawler identity.

**Result: PASS**

## Exercise 3 Conclusion

The acceptance matrix demonstrates that the reverse proxy correctly separates human and verified-crawler traffic.

Human and unverified requests continue to receive the original JavaScript SPA through the Vite origin. Verified crawler requests receive fully rendered HTML, with the first request generating and caching a Playwright snapshot and subsequent requests being served from cache.

Most importantly, spoofing a crawler User-Agent is insufficient to enter the prerender path, because crawler identity must also pass verification.
